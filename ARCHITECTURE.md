# Σuler.SC — Architecture Documentation

**Version:** 5.2.3  
**Last Updated:** 11.04.2026

## Overview

Σuler.SC is a symbolic calculator with AI-powered math assistance. The application runs locally on Windows/macOS/Linux, using Python for computation and a WebView-based UI for presentation.

## Technology Stack

### Backend (Python 3.10+)
- **SymPy** — symbolic computation engine (algebra, calculus, matrices)
- **pywebview** — native window with WebView2/WebKit bridge
- **Ollama** (optional) — local LLM inference for AI assistant
- **NumPy** — numerical operations and plotting

### Frontend (Web)
- **Vanilla JavaScript** — no frameworks, direct DOM manipulation
- **MathLive** — LaTeX equation editor
- **Marked** — Markdown rendering for AI responses
- **KaTeX** — formula rendering in AI chat

### Build & Distribution
- **PyInstaller** — standalone executable creation
- **NSIS** — Windows installer with dependency auto-setup

## Core Architecture

### 1. Security Model

**Threat:** User input comes from UI (typed), OCR (scanned), and LLM (AI-generated) — all untrusted sources.

**Defense Layers:**

1. **Parser (`euler/core/parser.py`)**
   - Blocks dangerous Python calls: `__import__`, `eval`, `exec`, `compile`, `lambda`
   - Blocks attribute access: `().__class__`, `__builtins__`, `__globals__`
   - Regex validation before AST processing
   - Raises `ExprError` with translation key (not raw input)

2. **Preprocessing**
   - Replaces Unicode superscripts/subscripts: `x²` → `x^2`
   - Normalizes multiplication: `2x` → `2*x`, `3(x+1)` → `3*(x+1)`
   - Rejects expressions with forbidden patterns

3. **SymPy Sandboxing**
   - All computation happens in SymPy (safe by design)
   - No `eval()` or `exec()` anywhere in codebase
   - Timeout protection: operations limited to 10 seconds (not yet implemented)

### 2. Transport: why not `js_api`

pywebview's `js_api` mechanism walks the API object with `dir()` and
`inspect.getfullargspec` to generate JavaScript stubs. On Windows that walk:

* recursed into the WebView2 window object, whose .NET members (`.SyncRoot`)
  reference themselves — `maximum recursion depth exceeded`, frozen window;
* or completed but produced no usable stubs, leaving `window.pywebview.api`
  empty. The interface then showed a keypad-less window with inert tabs and a
  status line stuck on "loading engine".

The fix is not a patch on that walk: it is replacing the mechanism.

**Design.** `euler/transport.py` starts a `ThreadingHTTPServer` bound to
`127.0.0.1` on an ephemeral port. The page is loaded from it, not from disk.
JavaScript calls `POST /api/<method>` with a JSON body of keyword arguments and
receives JSON back. Server-initiated progress (model download, AI tokens)
arrives over Server-Sent Events at `GET /events`.

**Security.** Seven layers guard the channel:

1. **Loopback only** — bound to `127.0.0.1`; nothing is reachable from a
   network.
2. **Host check** — the `Host` header must name `127.0.0.1`, `localhost` or
   `[::1]` with the serving port. This is the DNS-rebinding guard: a page on an
   attacker-controlled name can resolve to loopback, but the browser still sends
   its own `Host` and is refused. Until 5.2.0 the module docstring promised
   this check while no code performed it.
3. **Per-launch token** — `secrets.token_urlsafe(24)`, passed in the page URL
   and planted as an `HttpOnly; SameSite=Strict` cookie so sub-resource requests
   (`app.js`, `theme.css`) authenticate without a query string. Without the
   token every request gets `403`.
4. **Method allowlist** — `Api._exported` names the callable methods; the
   dispatcher refuses anything else, so a leaked token cannot reach arbitrary
   Python.
5. **Path containment by component** — `Path.is_relative_to()`, not
   `str.startswith()`. The prefix form accepted a sibling directory such as
   `app/web_secret`, because that string also begins with `app/web`.
6. **Body cap and origin check** — requests above 8 MiB are rejected, a
   non-numeric or negative `Content-Length` returns `400` instead of raising in
   the request thread, and a present `Origin` header must match the server.
7. **Export path containment** — `Api._export_path()` keeps only the final
   component of a caller-supplied filename, strips reserved and illegal
   characters, refuses Windows device names, and verifies the resolved target
   with `is_relative_to()` before writing. Before this, `filename="../../x"`
   and an absolute path both wrote outside `exports/`.

**Method surface.**

| Method | Parameters | Returns |
|--------|-----------|---------|
| `ready` | — | `{warm, version, methods}` |
| `solve` | `expression`, `matrices?` | `{ok, result, latex, form_key, forms}` |
| `solve_system` | `equations[]` | `{ok, result}` |
| `steps` | `expression`, `kind` | `{ok, title, steps[]}` |
| `calculus` | `kind`, `expression`, `a`, `b`, `direction` | `{ok, title, lines[]}` |
| `analyze` | `expression`, `interval?` | `{ok, function_latex, sections[]}` |
| `matrix_op` | `operation`, `first`, `second?`, `extra?` | `{ok, title, body, grid?}` |
| `matrix_save` / `matrix_get` / `matrix_delete` / `matrix_list` | name / grid | `{ok, ...}` |
| `cycle_form` | `expression` | `{ok, latex, key, forms[]}` |
| `plot` / `autoscale` | `equations[]`, `x_min`, `x_max`, `points` | `{ok, series[]}` |
| `export_pdf` / `export_latex` | `kind`, `payload`, `filename` | `{ok, path}` |
| `ai_ask` / `ai_stop` / `ai_reset` | `task`, `image_b64?`, `model?` | streams via SSE |
| `settings_get` / `settings_set` | `patch?` | `{ok, settings}` |
| `hardware`, `ollama_*`, `setup_all` | — | `{ok, ...}` |

**Positional arguments.** Call sites stay readable (`py('solve', '2+2')`)
because `app.js` keeps a `PARAMS` table mapping method name to parameter names
and converts positional arguments to the keyword object before sending.

### 3. Localization System

**File:** `app/web/i18n.js`

**Supported Languages:** Russian, English, Chinese, Spanish, French, Bengali,
Portuguese.

**Key counts:** 541 interface strings in every language, plus 99 engine error
messages (`ExprError.*`) each translated into all seven. Both sets are verified
programmatically: no language is missing an interface key, and no message lacks
a translation. Python never returns prose — it returns a stable key, and the
interface resolves it, so an error raised deep in `solver` still appears in the
user's language.

**Translation Flow:**

1. **Static HTML**: `data-i18n="key"` → `textContent`, `data-i18n-ph="key"` → `placeholder`
2. **Dynamic JS**: `t('key')` → translated string
3. **After Language Switch**: `I18n.apply()` updates HTML, `retranslateDynamic()` rebuilds keyboards/charts

**Storage:** Language preference saved to `settings.json`, restored on startup

### 4. Matrix Operations

**Input Format:** Grid of `<input>` cells (HTML) → 2D array of strings (JS) → SymPy `Matrix` (Python)

**Operations Returning Matrices:**
- Add `grid` field: `[[str]]` (2D array)
- UI fills grid back into cells via `writeMatrix()`
- User clicks "Result → A" to continue operation chain

**Example:**
```
User fills: A = [1,2; 3,4]
Click "Transpose" → Python returns grid=[['1','3'],['2','4']]
Click "Result → A" → UI writes grid into A cells
Click "Determinant" → det(transposed A) = -2
```

**Why Not `det(A)` Syntax?**  
Template grids are more intuitive for non-programmers. Function syntax would require:
- Variable manager UI (create/delete A/B/C/D)
- Expression parser for nested calls: `inv(A * B)`
- Error handling for undefined variables

Current grid approach: **zero cognitive overhead**, works like a paper worksheet.

### 5. Graph Rendering

**Two Modes:**

1. **Inline Canvas** (Analysis tab): Small, no labels, pan/zoom
2. **Fullscreen Overlay**: Large canvas with:
   - Axis labels (tick values on X/Y)
   - Function name in top-left
   - Controls: Reset view, Auto-fit Y, Close

**Sampling:**  
The engine takes a uniform pass, then refines only the intervals whose midpoint
deviates from the chord between its ends (`euler/core/grapher.py::_adaptive_grid`).
`x^3-3x` stays at ~900 points; `sin(1/x)` near zero spends 2000 where it needs
them. A uniform grid would either draw a steep section as a visible polygon or
waste thousands of points on a straight line.

**Discontinuity Handling:**  
A break is inserted when the value is not finite, or when the jump between
neighbours exceeds the local 5th–95th percentile spread by a wide factor. The
spread is computed per series, because the engine does not know the canvas
height; a steep-but-continuous curve never trips it, an asymptote always does.

**Auto-Scale Y:**  
Uses 2nd–98th percentiles of Y values → outliers (infinity at asymptotes) don't flatten the curve

### 5a. Annotations on the plot

**Model.** A stroke is `{id, tool, color, widthPx, fontPx, scale0, points, …}`
plus an affine matrix `m` in world coordinates. Moving, scaling and rotating
compose into `m`; the original points are never rewritten, so a stroke can be
restored exactly. Geometry lives in `app/web/drawgeom.js`, which touches no DOM
and is exercised directly under Node.

**Why world coordinates.** The first implementation stored screen pixels, which
made the drawing a sheet of glass in front of the camera: zooming left the ink
the same size and it slid over the curve instead of belonging to it. World
coordinates make ink behave like ink.

**Mapping.** `graphMapping()` mirrors `renderGraph`'s aspect fit exactly — the
same `visibleView()` decides both, so a stroke lands where the user clicked.

**Interactions.** Hand forwards the whole gesture (press, move, release) to the
plot canvas, so panning has one implementation. The drawing layer forwards wheel
events too, otherwise picking a pen silently disabled zoom. Select frames the
stroke with eight handles and a rotation knob; the frame is padded to 24 px
minimum so a horizontal line's handles never merge into its body.

### 6. Persistence

**File:** `settings.json` inside the application data directory — not in the
repository, not next to the executable.

| Platform | Path |
|---|---|
| Windows | `%APPDATA%\EulerSC\settings.json` |
| Linux | `~/.local/share/EulerSC/settings.json` |
| macOS | `~/Library/Application Support/EulerSC/settings.json` |

The same directory holds `logs/app.log` (rotating, 3 × 1 MB) and `exports/`.
A directory from the pre-5.0 name is migrated once, on first launch; a failed
`rename()` across filesystems falls back to `copytree()`.

**Writes are atomic:** content goes to a `.tmp` sibling and replaces the target,
so a crash mid-write cannot leave a half-written configuration. Every merge
passes through an allowlist (`DEFAULTS`), so a hand-edited or stale file cannot
inject unexpected keys.

**Stored state** (20 keys, from `euler/core/settings.py::DEFAULTS`):

| Key | Type | Purpose |
|---|---|---|
| `language` | str | interface language; empty means "use the installer's choice, then the browser locale" |
| `theme` | str | `auto` (follow the OS), `light`, `dark` |
| `model` | str | selected Ollama model tag |
| `temperature` | float | sampling temperature, default 0.3 |
| `angle_unit` | str | `deg` or `rad` |
| `points` | int | plot sampling density, default 1200 |
| `models_dir` | str | override for Ollama's model storage |
| `hardware` | dict\|null | cached probe result; `null` means "not probed yet" |
| `onboarding_done` | bool | first-run wizard completed |
| `matrices`, `matrix_order` | dict, list | saved grids `A`–`H` and their carousel order |
| `active_tab` | str | tab restored on next launch |
| `calculus`, `analysis` | dict | last inputs per tab: `fn`, `point`, `lower`, `upper`, `interval` |
| `graph`, `graph_functions`, `graph_marked` | dict, list, int | viewport, plotted expressions, marked series |
| `analysis_interval`, `equations` | str, list | last interval and last equation rows |

Matrices are deliberately persisted: losing an entered 5×5 matrix is
unacceptable, so a corrupt grid is skipped on load rather than aborting startup.

### 7. Boot sequence

The window must open **already correct**: right theme, right language, full
keypad, no half-drawn frame. Three separate moments used to be visible, and each
is now closed at a different layer.

**Why the theme used to flash.** `app.js` called `applyTheme()` only after
`settings_get` answered, so the document rendered with no `data-theme` first.
The CSS reads `prefers-color-scheme` in that state, so a user who pinned light on
a dark desktop saw a dark frame and then a repaint.

**Fix — resolve before the first byte.** `transport.boot_document()` reads
`settings.json` while serving `index.html` and rewrites the `<html>` tag:

```html
<html lang="ru" data-theme="light" data-booting>
```

`auto` writes no attribute at all, which is what lets the media query follow the
OS. Unreadable settings return the document untouched — a corrupt configuration
must never stop the interface from loading. Nothing changes after that first
frame, so there is no repaint to see.

**Why the keypad used to appear late.** The keypad, matrix grid and equation rows
are generated from JavaScript, so the first frames showed an empty calculator
body above an empty key grid.

**Fix — a boot cloak.** The served document carries `data-booting`. CSS hides
`.app` while it is present and paints the window in the body colour instead.
`init()` removes the attribute after the keypad exists, just before the engine
poll starts, so the user sees a complete interface with a live status line. A
3-second `setTimeout` removes it unconditionally: a visible working interface is
always better than a permanently blank window.

**Order inside `init()`** — deliberately, because a failure early must not leave
the interface inert:

1. keypad, then event binding (DOM only, cannot fail on the engine);
2. language, so no untranslated string is ever painted;
3. matrix grid and the first equation row;
4. **cloak lifted** — from here the interface is usable;
5. `ready()` polling, then `loadSettings()` and the first-run wizard.

**Engine readiness.** SymPy and NumPy take one to three seconds to import, so
the warm-up runs on a background thread. `ready()` reports `{ok, warm}`; if the
warm-up raised, it returns `ok: false` with the original exception text and
`_mod()` raises `EngineUnavailable` chained to it. Before 5.2.0 a failed warm-up
surfaced as `KeyError: 'solver'` on every request, which named an internal detail
and hid the cause.

### Testing

Two layers, both run before packaging:

```bash
pytest tests/ -q              # 168 unit tests, ~14 s
python tests/sweep_full.py    # 199 functional checks, release gate
```

**The reported total is 170, not 168, and that is deliberate.**
`tests/test_doc_counts.py` holds two tests whose job is to keep the numbers in
this documentation equal to the real ones. It counts the suite in a subprocess
with `--deselect tests/test_doc_counts.py`, because a file that counted itself
would never stabilise: adding a test to it would change both sides of the
equation at once. 170 collected minus those 2 equals the 168 quoted in the
documents. `test_documented_unit_count_is_current` fails with both numbers in
its message if the two ever disagree, so the convention cannot quietly rot.

**Unit tests** (`tests/test_*.py`) drive the modules directly and use
`monkeypatch` for anything that would touch the network, the filesystem or the
clock. Grouped by concern:

| File | Covers |
|---|---|
| `test_core.py` | parser allowlist, solver, matrices, calculus |
| `test_scenarios.py` | every tab's entry point through the public `Api` |
| `test_export.py` | PDF and LaTeX output |
| `test_settings.py` | atomic write, unknown-key dropping, defaults |
| `test_stepwise.py` | step generation per equation shape |
| `test_download.py`, `test_llm_download.py` | resumable download, checksum, Ollama client |
| `test_boot_and_ci.py` | boot document, engine gate, sweep guard |
| `test_syntax_floor.py` | every source file parses on the minimum Python |

**The release sweep** (`tests/sweep_full.py`) walks the input families a student
actually produces — arithmetic, logarithms with every base notation, equations,
systems, limits, integrals, derivatives, function study, matrices, exports — and
prints one `199/199 passed` line. It is the gate: a behaviour change without a
new check there is not finished.

**The sweep must survive any platform.** Each check runs inside a timeout from
`tests/_guard.py`: `signal.alarm` on POSIX, a daemon thread with a deadline on
Windows, which has no `SIGALRM` at all. Getting this wrong is what made the
Windows CI job fail on import rather than on a check.

**The minimum Python is enforced, not documented.** `test_syntax_floor.py`
re-parses every file with `ast.parse(..., feature_version=(3, 10))`. A
developer on 3.12 who writes a PEP 701 f-string — which allows a backslash
inside the braces — sees a failing test locally instead of a red job on three
platforms, which is exactly how 5.1.17 shipped a tree that 3.10 could not
import.

**What tests do not cover:** the rendered interface. Layout is verified by hand
in a real browser (or headless Chromium) at 960×720 and 1276×900, because the
matrix overflow and the theme flash were both invisible to every assertion.

### Upgrades

There is no separate updater: the installer upgrades. What makes that work is
one recorded fact and one comparison.

1. The previous run wrote `Version`, `VersionMajor/Minor/Patch` and `InstallDir`
   under `HKCU\Software\EulerSC`, after the files were in place — a version
   recorded for a failed copy would make the next run believe an installation
   exists.
2. `.onInit` reads them back, confirms the executable is really there (a registry
   entry with no files is debris from a failed uninstall and is ignored), and
   compares the installed numbers against the build's own from `version.nsh`.
3. Three outcomes: older installed → **upgrade**; equal → **repair**; newer
   installed → **downgrade**, refused unless `/FORCE` was passed.

The comparison is numeric per part, never a string compare: `5.10.0` must sort
above `5.9.0`, and a plain string comparison puts it below. Each part is coerced
with `IntOp`, so a truncated or hand-edited registry value degrades to `0`
instead of aborting a legitimate install.

During an upgrade the directory page is skipped: the shortcuts, the uninstall
entry and the `.tex` association all point at the recorded path, so moving it
would orphan them. User data lives in `%APPDATA%\EulerSC`, outside `$INSTDIR`,
which is why an upgrade does not need to preserve it — only the uninstaller
removes it. The test suite (`tests/test_installer_meta.py`) asserts these
properties textually, so a future edit cannot quietly drop them.

## Result formatting

`euler/core/format.py` answers one question: given a SymPy value, which
notation reads best?

| Value | Chosen | Alternatives |
|---|---|---|
| `6` | `6` | — |
| `11/2` | `5\frac{1}{2}` | `\frac{11}{2}`, `5.5` |
| `1/3` | `\frac{1}{3}` | `0.333…` (recurring: keep the fraction) |
| `0.25` | `0.25` | `\frac{1}{4}` |
| `\sqrt{125}` | `5\sqrt{5}` | `11.1803…` |
| `\pi` | `\pi` | `3.14159…` (never the default) |
| `1.2345e-5` | `1.2345 \times 10^{-5}` | `0.000012345` |

Rules: integers stay integers; terminating decimals read as decimals; recurring
ones stay exact fractions; radicals stay radicals; extreme magnitudes switch to
scientific. The ALT key cycles through every available form, and the value is
recomputed from the original expression each time, so precision is never lost to
round-tripping a display string.

## Step-by-step solutions

`euler/core/stepwise.py` uses two strategies:

1. **Rule based**, for the shapes a student meets: linear equations, quadratics
   (discriminant), term-by-term differentiation, standard integrals, limits with
   an indeterminacy and a series expansion. Steps are generated explicitly, so
   the output reads like a worked example.
2. **SymPy helpers** (`manualintegrate`, `dsolve` hints) when the rule table has
   no entry; their output is unpacked into numbered steps.

Each step is `{n, text, latex}`: the LaTeX is typeset in the interface, the text
is the short caption ("Compute the discriminant").

## Export

`euler/core/exporter.py` writes both formats without external binaries:

* `.tex` — a complete `\documentclass`…`\end{document}` file, compile with
  pdflatex or drop into Overleaf. Heading follows the interface language.
* `.pdf` — generated directly (page tree, Flate-compressed content stream,
  an embedded DejaVu Sans subset as Type0/Identity-H). LaTeX is converted to readable plain text first:
  `\frac{a}{b}` → `(a)/(b)`, `\sqrt{x}` → `sqrt(x)`, Greek and operators
  transliterated. A brace-matching reader handles nesting, which a regular
  expression cannot.

## Performance Characteristics

| Operation | Typical Time | Bottleneck |
|-----------|--------------|------------|
| Simple equation | 10–30 ms | SymPy parsing |
| Matrix 8×8 determinant | 50–150 ms | SymPy factorization |
| Definite integral | 100–500 ms | SymPy `integrate()` |
| Function analysis | 200–800 ms | Multiple SymPy calls (limit, derivative, solve) |
| Plot 900 points | 50–200 ms | SymPy `lambdify()` + NumPy eval |
| AI response (7B model) | 5–20 s | Ollama inference (10–50 tok/s depending on hardware) |

**Caching:** None currently. Each operation recomputes from scratch. Future: LRU cache for repeated expressions.

## Security Considerations

### Input Validation

**Never trust:**
- User-typed expressions
- OCR output (scanned homework)
- LLM output

**Pipeline** (`euler/core/parser.py`), in this order:

1. **Checks** — empty input and anything over 2000 characters are rejected
   before tokenizing.
2. **Token allowlist** — `tokenize.generate_tokens()` walks the input and every
   token must be a `NAME`, `NUMBER`, `OP` or whitespace marker. Any `STRING`,
   comment or line continuation is refused outright.
3. **Identifier allowlist** — every `NAME` must appear in `_SCALAR_NAMES`, plus
   the matrix names `A`–`H` and the matrix functions when a registry is present.
   Anything else (`__import__`, `eval`, `open`, `lambda`) never reaches SymPy.
4. **Dot rejection** — a `.` operator is refused, so no attribute access is
   possible, including dunder chains.
5. **Notation rewriting** — `%`, `log_b(x)`, decimal commas, mixed fractions and
   factorials are expanded into plain arithmetic *before* validation.
6. **`parse_expr` with an explicit `local_dict`** — the symbol table is built
   from the allowlist, so an unknown name cannot resolve even if it survived.

`sympify` is not used anywhere: it evaluates arbitrary Python and was the
original vulnerability. Errors are raised as `ExprError` carrying a message key,
never the raw input, so no user text is echoed back into the interface.

**Note:** there is no AST walk. Tokenization plus the identifier allowlist
achieves the same guarantee earlier and without constructing a tree.

### Sandboxing

- No `eval()`, `exec()` or `sympify()` anywhere in the codebase.
- SymPy runs in the same process. It is a trusted library, but a pathological
  expression can still run for a very long time — see Known Limitations 4.
- Ollama runs as a separate process and is talked to over HTTP on loopback.
- Exports are written only inside the application data directory: the caller's
  filename is reduced to its final component and the resolved path is checked
  with `is_relative_to()`.

### Data Privacy

- All computation happens locally
- No network requests except:
  - Ollama model download (explicit user action)
  - Optional: check for updates (not yet implemented)
- User data never leaves device

## Known Limitations

1. **No Multi-Variable Calculus**  
   Partial derivatives, multiple integrals not supported. Reason: UI complexity (3D plots, multiple input fields).

2. **No Equation Graphing in Implicit Form**  
   `x^2 + y^2 = 1` not supported. Workaround: solve for `y`, plot both branches.

3. ~~No step-by-step solutions~~ — implemented for linear/quadratic equations,
   derivatives, integrals and limits (`euler/core/stepwise.py`). Other shapes
   still return only the final answer.

4. **No timeout on evaluation — a pathological expression can occupy a worker**  
   `9**9**9` passes validation and does not finish in any useful time. Because
   evaluation runs inside `ThreadingHTTPServer` request threads and CPython holds
   the GIL during integer exponentiation, that thread stays busy: the window keeps
   responding, but one worker never returns. `signal.alarm()` is not an option —
   signals are delivered only to the main thread, and Windows has no `SIGALRM` at
   all. The correct fix is process isolation: evaluate in a child process and
   `terminate()` it at the deadline, because a thread cannot be killed. Not yet
   implemented; the release sweep uses a per-case guard (`tests/_guard.py`) so it
   cannot hang the CI job in the meantime.

5. **Complex numbers in matrix output**  
   Eigenvalues with an imaginary part still print as `(2+3j)`; the formatter
   handles real values only.

6. **CJK glyphs are missing from PDF formulas**  
   Body text uses an embedded Unicode face (`pdf_font.py`, `Type0 / Identity-H`),
   so Cyrillic and Latin render correctly. Formulas go through matplotlib's
   `mathtext` with DejaVu Sans, which has no CJK glyphs: a Chinese formula exports
   with blank boxes and a `Glyph missing from font` warning. Exporting LaTeX
   avoids this, since `pdflatex` with `ctex` handles the full character set.

## Rewriting history

`build/euler/` — PyInstaller's work directory — was committed once and removed
from the index in 5.2.0. Removing a path from the index does not remove it from
history: every clone still downloads it. Cleaning that up is a one-off,
irreversible rewrite, so it is done deliberately and never automatically.

### What is wrong

```bash
git log --all --oneline -- build/euler | wc -l     # commits that carry it
git rev-list --objects --all | grep build/euler    # blobs still reachable
du -sh .git                                        # what a clone pays
```

In this repository that is 2 commits and 24 tracked artefact objects.

### The rewrite

`git filter-repo` is the maintained replacement for `filter-branch`, which the
git project itself recommends against. Install it once
(`pip install git-filter-repo`, or `brew install git-filter-repo`), then work
from a **fresh clone**, never your working copy: `filter-repo` rewrites in place
and refuses a dirty tree.

```bash
# 0. Work on a copy.
git clone <remote> euler-clean && cd euler-clean

# 1. Drop the directory from every commit on every branch.
git filter-repo --path build/euler --invert-paths

# 2. filter-repo strips the remote; put it back.
git remote add origin <remote>

# 3. Inspect before publishing. The working tree must be unchanged.
git log --oneline -5
git rev-list --objects --all | grep -c build/euler    # must print 0
du -sh .git
```

### Publishing

A rewrite changes every commit hash, so the push must be forced and every
collaborator must re-clone. Any open pull request needs rebasing.

```bash
# Tags are rewritten too, so they need the same treatment.
git push --force-with-lease origin --all
git push --force-with-lease origin --tags
```

`--force-with-lease` rather than `--force`: it refuses the push if someone else
pushed in the meantime, which is the difference between a clean rewrite and
silently discarding a colleague's work.

### Afterwards

- Every collaborator re-clones. A `git pull` on an old clone merges the old
  history back in and undoes the cleanup.
- GitHub keeps unreachable objects until it runs its own garbage collection;
  ask support to run `git gc --prune=now` if the repository size matters at once.
- `dist/` and `EulerSC-*.zip` are already ignored, so this only has to happen
  once.

## Understanding a question

Three layers, cheapest first. The order matters: the model is slow, so it only
sees what the cheap layers could not resolve.

```
1. reference.rank()          phrases + keywords + formula shape       ~7 ms
   confident hit  ──────────────────────────────────────────────►  answer

2. intent.classify()         model picks from a shortlist of real ids  ~2 s
   theory + valid id, confidence >= 0.55 ───────────────────────►  answer

3. neither                   ──────────────────────────────────►  ask the user
```

**Layer 1 — descriptions.** `reference.PHRASES` maps how people actually speak
to entry ids: "квадрат гипотенузы" → `pythagoras`, "вероятность ровно k
успехов" → `bernoulli`. This is not guessing; it is a recognised formulation.

**Layer 2 — the model.** `intent.py` sends a shortlist of plausible ids and
asks for one JSON object: `{"intent", "theorem", "confidence"}`. Ollama is put
in JSON mode, so the reply always parses. Two safeguards make a small model
usable here:

* `_coerce()` drops any id that is not in the shortlist. A 0.5B model invents
  plausible-looking ids; validation turns that from a bug into a miss.
* Below `MIN_CONFIDENCE` a "theory" verdict becomes a question. A wrong card
  teaches the reader to distrust the panel, so the pipeline asks instead.

Results are cached by normalised text, so the same wording costs one model call
in the session, not one per keystroke.

**Layer 3 — asking.** When nothing is certain the user gets "уточните,
пожалуйста" plus two examples of the shape that works. The question is dropped
from history: a follow-up must not inherit a message the assistant declined to
interpret.

### Why not always use the model

A classifier pass costs 1.5–3 s on a 0.5B model running on CPU. Running it
before every answer would make the calculator feel slow to solve `2+2`. The
lexical layer answers most questions in single-digit milliseconds; the model is
reserved for the phrasing nobody anticipated.
